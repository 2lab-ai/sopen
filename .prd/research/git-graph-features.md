# Git Graph feature inventory — reference for sopen's git panel

## 1. Header

Evidence: [SOURCE] repository at v1.30.0 (commit 881a9e613045bacbbadf8940f6b6c5b8bd699335) + README/marketplace; not operated live — behaviour beyond what the source shows is marked (estimate)

**Purpose.** The owner asked (2026-11-20, verbatim): "그리고 만약 폴드가 git 폴더면 vscode중에 git graph있는데 그거 … 해당 git graph 기능 모두 뽑아서 해당 기능처럼 자유롭게 git 작업할 수 있도록해줘. 전체 커핏이랑 브랜치 그래프 볼수 있고 커밋 편집 최대한 자유롭게 할수 있게 해줘." This file lists every feature of the VS Code extension Git Graph (`mhutchie.git-graph`): what it shows, every action, the exact git command lines it runs, every setting, every shortcut. Section 7 lists the history edits it does not offer, and section 8 lists what needs care when git runs over ssh. The sopen spec uses it to define a git panel that reproduces the workflow. The panel would sit in the file browser (spec §3a), shown when the opened folder is a git work tree. It is a reproduction of the behaviour, not a port: nothing here is code to copy (see Licence). The panel is a new owner request. The spec's §1/§2 still have to take it in, and AGENTS.md's "the file browser adds viewing, not file operations" rule has to be revisited there. That is spec work, not this file's.

**How this was built.**

- Read at the tag: `README.md`, `package.json` (`contributes`), the webview `web/*.ts` (context menus, dialogs, find widget, settings widget, graph, keyboard handling) and the extension side `src/*.ts` (`dataSource.ts` holds every git command line; `gitGraphView.ts` routes webview requests to it).
- Every table row cites a permalink at the commit above. Rows in §7 and §8 cite where Git Graph does (or, by a zero-hit search, does not) handle the concern.
- Git Graph is not installed in VS Code on the machine this was written on, and its GUI was not operated. Anything not visible in the source is marked (estimate).
- Some plain-git behaviours in §7–§8 were checked in a throwaway repository with git 2.56.1, with no terminal (stdin `/dev/null`). They are marked (verified, git 2.56.1).
- Every other plain-git form, option or version floor in §7–§8 comes from git's documentation and was not run here. Treat it as (estimate) unless marked (verified).
- Coverage was reconciled against two indexes: the 47 `contextMenuActionsVisibility` keys and the 61 webview request types (§4.8). The whole CHANGELOG (1.2.0–1.30.0) was skimmed for features without a row.

## 2. View — what the graph view shows and how it loads

The view is one webview tab: a control bar, then a table whose first column is an SVG graph, then a footer. "Per repository" below means the view stores the value for that repository and it overrides the matching `git-graph.*` setting (§5).

## 4. Actions

Every action below is a right-click context-menu item unless noted. Each one can be hidden through `git-graph.contextMenuActionsVisibility` (§5), and items are also hidden when they do not apply (noted per row). An item ending in "…" opens a dialog first. The primary (left) button runs the action, Enter submits, and Escape cancels. Every git command runs as a child process `git <args>` in the repository root (argv, no shell), with `GIT_ASKPASS` set (§8). A refresh follows success ([web/main.ts:3334-3352](https://github.com/mhutchie/vscode-git-graph/blob/881a9e613045bacbbadf8940f6b6c5b8bd699335/web/main.ts#L3334-L3352)).

Shared conventions:

- `-S` is appended to merge, pull, cherry-pick, revert, rebase, drop and the squash commit when `repository.sign.commits` is on. Annotated tags use `-s` instead of `-a` when `repository.sign.tags` is on.
- Branch- and tag-name inputs are validated against git's ref-name rules as you type. The OK button stays disabled for an invalid name. Spaces can be auto-replaced with `-` or `_` (`dialog.general.referenceInputSpaceSubstitution`).
- Dialog defaults come from `git-graph.dialog.*` (§5.4).

## 8. Running these over ssh on a remote repository

Git Graph runs git locally as a child process (`spawn`, argv array, no shell, no TTY, stdin unused) and adds only its askpass variables to the environment: `GIT_ASKPASS` plus the helper's own `ELECTRON_RUN_AS_NODE` / `VSCODE_GIT_GRAPH_ASKPASS_*` ([src/dataSource.ts:1720-1738](https://github.com/mhutchie/vscode-git-graph/blob/881a9e613045bacbbadf8940f6b6c5b8bd699335/src/dataSource.ts#L1720-L1738) [src/askpass/askpassManager.ts:77-89](https://github.com/mhutchie/vscode-git-graph/blob/881a9e613045bacbbadf8940f6b6c5b8bd699335/src/askpass/askpassManager.ts#L77-L89)). sopen's panel would run the same commands on the file's host through the system `ssh` binary (spec §4: one multiplexed master per host; "the remote needs only sshd"). That is the same no-TTY situation, plus a remote shell parsing the command line. Forms marked (verified, git 2.56.1) were run without a terminal; the rest are from git's documentation (estimate). A search of `src/` and `web/` finds 0 hits for `GIT_TERMINAL_PROMPT`, `core.pager`, `no-verify`, `LC_ALL` and `LANG`: Git Graph sets none of them.
